# 화면 계약

이 문서는 사용자에게 보이는 라우트, 상태, 목록, 상세 모달과 기업정보 화면을 소유한다. 데이터 이름과 오류 형식은 [02-data-and-api.md](02-data-and-api.md)를 따른다.

## 라우트와 접근

| 경로 | 화면과 동작 |
| --- | --- |
| `/` | 로그아웃 상태는 소개, 로그인 상태는 `/company` 또는 `/announcements`로 이동 |
| `/login` | 로그인 폼. 로그인 상태는 적절한 앱 첫 화면으로 이동 |
| `/announcements` | 전체 공고 목록 |
| `/announcements/:id` | 공고 목록 위에 공용 상세 모달을 여는 주소 |
| `/interests` | 관심 상태가 설정된 공고 목록 |
| `/company` | 기업정보 조회·수정 |

소개와 로그인만 공개한다. 로그인 뒤 기업명이 비어 있으면 `/company`, 그렇지 않으면 `/announcements`로 이동한다. 인증된 API가 401을 반환하면 로그인으로 이동하고 성공 후 원래 URL로 복귀한다. 로그인 요청 자체의 401은 폼 오류로 표시한다.

정의되지 않은 URL은 이동시키지 않고 `404`, `페이지를 찾을 수 없습니다`, `입력한 주소가 올바른지 확인해 주세요`를 표시한다. 로그아웃 상태는 `/`, 로그인 상태는 `/announcements`로 돌아가는 버튼을 제공한다.

내비게이션은 `전체 공고`, `관심 공고`, `기업정보`다.

## 공통 레이아웃

- 밝은 베이지 배경과 절제된 주황 강조색을 사용한다.
- 판정 색은 신청 가능 녹색, 확인 필요 주황색, 신청 어려움 빨간색이다.
- 라이트 모드만 제공한다.
- 데스크톱은 접을 수 있는 사이드바, 모바일은 shadcn Sheet를 사용한다.
- 공고는 정보 밀도가 높은 반응형 카드로 표시한다.
- 모바일과 데스크톱의 기능은 같다.
- 키보드로 내비게이션, 필터, 폼과 모달의 모든 동작을 수행할 수 있어야 한다.

## 상태 표시

작업 상태와 사용자 판정을 섞지 않는다.

- 최초 분석이 QUEUED 또는 RUNNING인 공고는 사용자 목록에서 숨긴다.
- 최종 시스템 실패는 `확인 필요`와 고정 실패 설명으로 공개한다. 실패를 `신청 어려움`으로 표시하지 않는다.
- 기업정보 변경 뒤 재판정 전 결과는 `기업정보 변경 전 결과`로 명시한다.
- 기간을 해석하지 못한 공고는 `기간 확인 필요`로 표시한다.
- 필터 결과가 없는 상태와 수집된 데이터 자체가 없는 상태를 다른 문구와 다음 행동으로 안내한다.
- 로딩 또는 조회 실패 상태에는 존재하지 않는 판정·근거·관심 제어를 임시로 표시하지 않는다.

날짜는 유효한 `YYYY-MM-DD`, 시각은 timezone이 포함된 ISO 8601만 받는다. Asia/Seoul 기준 날짜는 `2026. 9. 4.`, 시각은 24시간제 `2026. 9. 4. 00:00` 형식으로 표시한다. 값이 없거나 유효하지 않으면 `확인 필요`다.

## 공고 목록

- 서버 페이지네이션을 사용하며 페이지 크기와 정렬은 [목록 API 계약](02-data-and-api.md#목록과-오류)을 그대로 따른다.
- 숫자 페이지, 이전·다음, 전체 건수와 현재·전체 페이지를 표시한다.
- 필터는 키워드, 신청 판정, 모집 상태, 관심 상태다. 변경하면 첫 페이지로 이동한다.
- 키워드는 제목, 주관기관, AI 요약과 추출 조건을 검색한다.
- 카드는 제목, 기관, 신청 기간, 판정 배지, 한 줄 AI 사유와 관심 상태를 표시한다.
- 마감 공고는 모집 상태 필터로 조회한다. 정상 카드에는 별도 모집 상태 배지를 반복하지 않는다.
- 관심 공고에서도 자격 판정은 그대로 표시하며 관심 상태로 판정을 바꾸지 않는다.

진행률 배너나 근거 없는 퍼센트는 만들지 않는다. 적합도 점수와 추천 순위도 표시하지 않는다.

## 공용 상세 모달

`/announcements`와 `/interests`, 직접 상세 URL은 같은 상세 컴포넌트를 사용한다. 목록에서 열면 URL을 `/announcements/:id`로 바꾸고 뒤로가기, X, Esc 또는 바깥 영역으로 닫을 때 기존 query string, 페이지와 scroll 위치를 복원한다. 직접 URL로 들어오면 기본 공고 목록을 배경으로 열고 닫으면 `/announcements`로 이동한다.

데스크톱은 넓은 모달, 모바일은 전체 화면에 가까운 모달이다. 모달은 `본문 스크롤 영역 + 비스크롤 하단 행`으로 나눈다. 하단 행에는 `관심 있음`, `보류`, `관심 없음` 세 버튼만 동일 너비 3열로 둔다. 로딩·조회 실패 중에는 하단 행을 표시하지 않는다.

본문 순서는 다음과 같다.

1. 최종 판정, 통과한 지원유형 또는 선택 역할
2. AI 요약과 결과 설명
3. 필수·우대·이행 조건 전체, 조건별 상태와 원문 근거
4. 공고 기본정보
5. 저장된 첨부파일과 기업마당 원문 링크

근거는 모달 안에서 펼치며 PDF·이미지는 페이지, Office 문서는 파일명을 표시한다. 저장 첨부와 기업마당 원문은 새 탭으로 연다. 별도 닫기 버튼은 두지 않고 Dialog X를 사용한다.

역할별 공고는 역할별 예상 결과를 보여 주고 모달 안에서 역할을 선택한다. UNKNOWN 조건은 기업정보 수정 또는 공고별 답변 입력으로 연결한다. 선택 뒤 202를 받으면 이전 결과를 `변경 전 결과`로 표시하고 새 결과가 공개될 때 갱신한다.

## 기업정보

한 화면 안의 섹션 카드로 구성한다. 필드와 wire 형식은 [기업정보 계약](02-data-and-api.md#기업정보-wire-contract)을 사용한다.

- 지역은 검색 결과에서 선택하며 내부 코드를 직접 입력하거나 화면에 노출하지 않는다.
- 업종, 인증, 역량과 키워드는 추가·삭제 가능한 태그형 목록이다.
- 매출은 천 단위 쉼표와 `원`을 표시한다.
- 선택 입력의 빈값은 미확인이다. 기업규모에는 사용자가 명시적으로 고를 수 있는 `미확인`도 제공한다.
- 입력 중 오류를 해당 필드 아래 표시하고 오류가 하나라도 있으면 저장 요청을 보내지 않는다.
- 정상 상태에는 글자수, 개수와 최댓값 안내를 노출하지 않는다.
- 422의 필드 위치를 해당 입력과 연결하며 나머지 API 오류도 서버 code 또는 message를 보존해 보여 준다.
