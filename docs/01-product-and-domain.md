# 제품과 도메인 계약

이 문서는 사용자에게 보이는 용어, 판정 의미, 판정 집계와 기업정보의 도메인 의미를 소유한다. wire 형식은 [02-data-and-api.md](02-data-and-api.md), 의도적인 완화 규칙은 [07-decisions.md](07-decisions.md)를 따른다.

## 용어와 상태

### 사용자 판정

| 화면 문구 | enum | 의미 |
| --- | --- | --- |
| 신청 가능 | `ELIGIBLE` | 선택한 지원유형 또는 역할의 모든 명시적 필수조건이 통과함 |
| 확인 필요 | `NEEDS_CONFIRMATION` | 명시적 실패는 없지만 값, 역할, 원문, 변환 또는 분석이 부족하거나 모호함 |
| 신청 어려움 | `INELIGIBLE` | 하나 이상의 명시적 필수조건이 명확하게 실패함 |

공개 가능한 공고는 세 판정 중 정확히 하나를 가진다. 작업 상태는 `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED_RETRYABLE`, `FAILED_FINAL`이며 사용자 판정 enum과 분리한다.

관심 상태 `관심 있음`, `보류`, `관심 없음`은 사용자가 정하는 별도 축이다. 처음 선택하기 전에는 미설정값을 허용하며 관심 상태는 자격 판정에 영향을 주지 않는다.

## 판정 엔진

조건 결과는 `PASS`, `UNKNOWN`, `FAIL`, `NOT_APPLICABLE`이다.

1. 적용되는 필수조건에 `FAIL`이 하나라도 있으면 `INELIGIBLE`이다.
2. `FAIL`이 없고 `UNKNOWN`이 하나라도 있으면 `NEEDS_CONFIRMATION`이다.
3. 적용되는 필수조건이 모두 `PASS`일 때만 `ELIGIBLE`이다.

필수조건은 `ALL`과 `ANY` 그룹 트리로 표현한다.

- `ALL`: 자식 하나가 FAIL이면 FAIL, 그 외 UNKNOWN이 있으면 UNKNOWN, 나머지는 PASS
- `ANY`: 자식 하나가 PASS이면 PASS, 그 외 UNKNOWN이 있으면 UNKNOWN, 모든 자식이 FAIL이면 FAIL
- 적용 가능한 자식이 없거나 모두 NOT_APPLICABLE이면 UNKNOWN
- 지원유형·역할별 루트 그룹 하나가 하나의 eligibility path다.
- path 하나가 PASS면 공고는 ELIGIBLE, PASS 없이 UNKNOWN path가 있으면 NEEDS_CONFIRMATION, 모든 path가 FAIL이면 INELIGIBLE이다.

우대, 가점, 권장, 안내, 선정 후 이행사항과 증빙 준비 여부는 최종 판정을 바꾸지 않는다. 필수 여부가 불명확한 문장은 UNKNOWN으로 남긴다.

Python이 날짜, 숫자, enum과 지역처럼 결정 가능한 비교를 소유한다. AI 판단은 코드로 확정된 결과를 뒤집을 수 없다. 숫자 조건은 대상, 단위, 연산자와 대응 기업정보 필드가 모두 일치할 때만 자동 비교한다.

## 지원유형과 역할

- 여러 지원유형 중 하나의 path라도 PASS면 공고는 ELIGIBLE이며 통과한 유형을 표시한다.
- 주관기관, 참여기관, 수요기업처럼 역할별 조건이 다르면 선택 전에는 NEEDS_CONFIRMATION이며 역할별 예상 판정을 보여 준다.
- 역할 선택은 해당 공고만 다시 판정한다.
- 필수 협력기관 정보가 없으면 NEEDS_CONFIRMATION이다.
- 선택 역할은 사용자·공고·공고버전 단위로 이력을 남긴다. 새 공고버전에 같은 역할이 없으면 현재 선택을 해제하고 다시 확인받는다.

## 특수 판정 규칙

- 업력은 공고의 명시 기준일을 우선하고, 없으면 게시일을 사용한다.
- `<`, `<=`, `>`, `>=`와 범위 경계의 포함 여부를 원문 그대로 보존한다.
- 자격 정보가 거의 없거나 조건을 추출하지 못하면 NEEDS_CONFIRMATION이다.
- 향후 채용·이전·투자 등 선정 후 의무는 `신청 후 이행사항`으로 표시한다.
- 증빙 보유 여부가 없더라도 기업정보의 자격값으로 비교하고 필요한 증빙만 안내한다.
- 체납 있음은 공고에 체납 제한이 명시된 경우에만 FAIL이다.
- 지원 수혜 이력은 동일·유사·후속 사업이 명백할 때만 FAIL이고 애매하면 UNKNOWN이다.
- 자유 입력 업종은 공고 업종과의 동일·포함 관계를 판단하되 양쪽 근거를 남긴다.
- `전국`과 `국내`는 특정 지역 제한으로 추출하지 않는다. 비교 가능한 지역이 명확히 불일치하면 FAIL이고, 지역 변환 실패나 동명 지역은 UNKNOWN이다.

## 기업정보

한 계정은 한 기업만 관리한다. 화면과 사용자 문구는 `기업정보`로 통일한다. 기업명만 필수이며 나머지 빈값은 미확인이다.

| 그룹 | 의미 |
| --- | --- |
| 기업명 | 판정 대상 기업의 명칭 |
| 사업자 형태 | 개인사업자 또는 법인 |
| 조직 속성 | 영리, 비영리, 협동조합 또는 생산자단체 |
| 기업규모 | 소상공인, 소기업, 중기업, 중견기업, 대기업 또는 미확인 |
| 설립일 | 업력 계산에 사용하는 정확한 날짜 |
| 적용 가능 지역 | 공식 행정코드와 명칭으로 선택한 복수 지역. 장소 유형은 구분하지 않음 |
| 업종 | 주업종 하나와 부업종 목록. 코드는 받지 않음 |
| 규모 정보 | 기준연도 없는 최근 매출액과 기준일 없는 현재 상시근로자 수 |
| 자격 | 통합 체납 여부와 유효기간 없는 인증명 목록 |
| 이력 | 사업명과 연도로 구성한 정부지원 수혜 이력 |
| 역량 | 제품·서비스·기술 태그. 명시적 자격조건에 관련될 때만 판정에 사용 |
| 선호 | 관심·제외 키워드. 탐색에만 사용하고 판정에는 사용하지 않음 |

다음 정보는 받지 않는다: 사업자등록번호, 영업·휴업·폐업·부도 상태, 신청 제한·제재, 장소 유형, 업종 코드, R&D 조직·연구인력, 매출 기준연도, 근로자 기준일·연평균 인원, 인증 유효기간. 공고가 이를 필수조건으로 요구하면 [승인된 완화 결정](07-decisions.md#d-02-기업정보-완화-규칙)이 적용되는 경우를 제외하고 UNKNOWN이다.

## 입력 검증

- 문자열은 앞뒤 공백을 제거하고 공백뿐인 선택값은 null로 정규화한다.
- 기업명은 1~100자, 업종·인증·태그·사업명은 항목당 100자, 메모는 1,000자 이하다.
- 적용 가능 지역, 부업종, 인증, 역량 태그, 관심·제외 키워드는 각각 최대 50개이며 수혜 이력은 최대 100개다.
- 설립일은 미래일 수 없다.
- 매출액은 0 이상 100,000,000,000,000,000원 이하 정수, 근로자 수는 0 이상 10,000,000명 이하 정수다.
- 수혜연도는 1900년부터 현재연도까지다.
- 목록 중복은 유니코드, 대소문자와 공백을 정규화한 뒤 제거한다.
- 기업규모의 명시적 미확인과 미입력은 판정에서는 같은 UNKNOWN이지만 원 입력은 버전에 보존한다.

입력 중 즉시 오류를 표시하고 오류가 있으면 저장을 막는다. 정상 상태에는 글자수·개수 제한 안내를 표시하지 않는다.

## 판정을 바꾸는 입력

사용자는 최종 판정을 직접 덮어쓸 수 없다. 기업정보 수정, 역할 선택, 공고별 답변 또는 재분석만 판정을 바꾼다.

UNKNOWN 조건에서 만드는 공고별 질문은 조건 ID, 필요한 자료형, 선택지 또는 단위와 원문 근거를 가진다. 답변 출처는 `사용자 직접 확인`, `공식 서류`, `기관 문의` 중 하나와 선택 메모다. 답변은 해당 조건과 공고버전에만 적용하며 공통 기업정보로 자동 승격하지 않는다. 공고버전이 바뀌면 이전 답변으로 표시하고 다시 확인받는다.
