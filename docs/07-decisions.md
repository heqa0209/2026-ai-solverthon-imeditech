# 구현 결정 기록

이 문서는 안전성·정확도·운영성의 절충 때문에 의도적으로 선택한 결정과 이유를 소유한다. 각 결정은 변경 전 사용자 확인이 필요하다.

## D-01. 판정 권한과 근거

상태: 승인

결정: Python 규칙이 비교 가능한 자격 판정을 소유하고 AI는 조건 추출, 비정형 의미판단, 검증과 설명을 맡는다. 모든 공개 조건과 설명에는 저장된 원문 근거가 있어야 한다.

이유: 의미가 비슷하다는 이유만으로 명시적 자격 불일치를 통과시키거나, 근거 없는 AI 설명을 판정처럼 보이는 위험을 막는다.

## D-02. 기업정보 완화 규칙

상태: 위험을 이해하고 승인

결정: 다음 대체값을 허용하고 사용한 조건에 `assumption_code`와 설명을 남긴다.

- 장소 유형을 저장하지 않으므로 저장된 적용 가능 지역을 본사·공장·사업장 요구에 사용할 수 있다.
- 매출 기준연도를 저장하지 않으므로 최근 매출을 특정 연도 요구에 사용할 수 있다.
- 근로자 기준일을 저장하지 않으므로 현재 인원을 특정 기준일·연평균 요구에 사용할 수 있다.
- 인증 유효기간을 저장하지 않으므로 등록된 인증을 유효한 것으로 간주한다.
- 사용자가 선택한 기업규모를 별도 검증 없이 확정값으로 사용한다.

위 가정은 더 보수적인 동작으로 임의 변경하지 않는다. 공고가 요구하는 미수집 정보에 이 목록의 대체 규칙이 없으면 UNKNOWN이다.

## D-03. PDF 부분 텍스트 OCR 생략

상태: 정확도 위험을 이해하고 승인

결정: PDF에서 네이티브 텍스트가 한 부분이라도 추출되면 이미지 전용 페이지를 찾기 위한 추가 OCR을 하지 않는다.

이유: 대회 MVP의 처리 시간과 비용을 제한한다. 누락 위험은 fixture와 원문 열기 기능으로 드러내며 이 정책을 조용히 페이지별 혼합 OCR로 바꾸지 않는다.

## D-04. Codex CLI OAuth와 격리

상태: 운영 위험을 이해하고 승인

결정: 이 Mac의 Codex OAuth와 비대화형 CLI를 별도 worker에서 사용한다. public request가 프롬프트, CLI 인자, 작업 디렉터리와 도구 권한을 제어하지 못하게 고정 backend contract 뒤에 격리한다.

이유: 대회 환경에서 사용 가능한 인증을 사용하되 공개 서비스가 로컬 Codex 권한으로 이어지는 경로를 차단한다. OAuth가 중단되면 작업을 대기시키고 운영자가 터미널에서 복구하며 다른 공급자로 자동 전환하지 않는다.

## D-05. AI 모델 배치

상태: 승인

결정: [모델·effort 매트릭스](03-ingestion-and-ai.md#모델과-effort)에 조건부 최종 검증 단계를 유지한다. 이 단계는 AI가 직접 내린 복잡한 판단 또는 판정을 좌우하는 OCR 근거가 있을 때만 실행한다.

이유: 모든 공고를 최고 비용 모델에 보내지 않으면서 판정을 좌우하는 비정형 판단에 독립 검증을 둔다. Sol을 수동 감사로만 제한했던 과거 spec은 현재 계약이 아니다.

## D-06. 기업정보 AI 전송

상태: 승인

결정: 판정에 사용하는 저장된 기업정보 전체를 해당 공고의 AI 단계에 보낼 수 있다. 대상 사용자·기업정보버전·공고버전과 모델을 실행 전에 고정하고 일반 로그에는 원문을 남기지 않는다.

이유: 자유 업종과 중복수혜 같은 의미 비교에 기업 사실이 필요하다. 다른 사용자나 대량 대상까지 실행 범위를 넓히는 것은 별도 승인이 필요하다.

## D-07. 불변 버전과 장기 보존

상태: 승인

결정: 공고 원본, 첨부, 기업정보, AI 단계, 조건 결과와 판정을 불변 버전으로 연결하고 관리자가 별도 보존 정책을 승인하기 전까지 유지한다.

이유: 어떤 입력과 근거가 공개 판정을 만들었는지 재현하고 변경 전 결과를 역사적으로 설명해야 한다.

## D-08. 설명 실패의 공개 판정

상태: 승인

결정: 계산이 끝났지만 사용자용 설명 생성이 최종 실패하면 계산 판정은 내부에 보존하고 공개 판정만 NEEDS_CONFIRMATION, 원인은 SYSTEM_FAILURE로 둔다.

이유: 설명 없는 확정 판정은 원문 근거를 확인하기 어렵지만 실제 자격 계산 실패와도 구분해야 한다.

## 반입하지 않는 과거 계약

다음 항목은 참고 자료에 있더라도 현재 제품 계약으로 복원하지 않는다.

- 다기업·다구성원·기업 관리자 모델
- 이메일 회원가입, JWT access·refresh 인증
- 적합도 점수, 추천 정렬, 강점·위험 점수화
- 기업 문서 업로드와 일회성 AI 추출
- 최신 행만 유지하고 이력·감사를 버리는 데이터 모델
- AI 전체 원시 응답 저장
- 작업 상태를 사용자 판정처럼 직접 노출하는 UI
- CORS를 어떤 배포 구조에서도 금지하는 규칙
- DB volume 삭제를 정상 초기화·복구 절차로 사용하는 방식
